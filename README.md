# Финансовый менеджер семьи — Telegram-бот + веб-панель

Тестовое задание: сервис учёта семейных расходов. Член семьи пишет боту в
Telegram «кофе 350» — и трата сохраняется: бот сам определяет сумму,
категорию и дату. Глава семьи видит и редактирует траты всех членов семьи
через веб-панель.

## Статус

На данный момент реализовано:

- **Модель данных и бизнес-логика.** Сущности «член семьи» (с ролью
  `member`/`admin`) и «трата» (с фиксированным набором категорий), CRUD
  и правило доступа: обычный член семьи видит и правит только свои траты,
  глава семьи (admin) — все.
- **PostgreSQL**: две таблицы (`users`, `expenses`), миграции применяются
  автоматически при старте.
- **REST API** — тот же набор эндпоинтов будет использовать и веб-панель,
  и бот (после подключения LLM-агента):
  - `POST /api/expenses` — добавить трату
  - `GET /api/expenses?user_id=&category=&from=&to=` — список с фильтрами
  - `GET /api/expenses/last?user_id=` — последняя трата (для правок вида
    «последнее было не 350, а 450»)
  - `GET /api/expenses/{id}`, `PATCH /api/expenses/{id}`,
    `DELETE /api/expenses/{id}`
  - `GET /api/users` — список членов семьи

  Кто вызывает — определяется заголовком `X-Telegram-User-Id`. Без
  заголовка запрос считается «веб-панелью» и получает полный доступ
  (авторизация для панели по заданию не нужна).
- **Telegram-бот**: пока отвечает на `/start` и автоматически
  регистрирует отправителя как члена семьи. Обработка свободного текста
  («кофе 350», «удали такси» и т.п.) через LLM — следующий шаг.
- **Тесты** на HTTP-слое (`go test ./...`), проверяют именно разграничение
  прав доступа (член не видит и не может редактировать чужие траты ни
  напрямую, ни через параметры запроса).

Пока не реализовано: LLM-агент для разбора естественного языка в боте и
веб-фронтенд панели.

## Стек

- Backend: Go, `chi` (роутинг), `pgx` (Postgres), `go-telegram-bot-api`
- БД: PostgreSQL
- Запуск: Docker Compose

## Структура проекта

```
cmd/app/              — точка входа (только сборка зависимостей и запуск)
internal/
  domain/             — сущности и бизнес-правила без внешних зависимостей
  usecase/            — CRUD над тратами + проверка прав доступа
  storage/postgres/   — реализация репозиториев + миграции
  httpapi/            — REST API
  telegram/           — адаптер Telegram-бота
  config/             — загрузка конфигурации из .env/переменных окружения
```

## Запуск

1. Скопировать `.env.example` в `.env` и заполнить:
   - `TELEGRAM_BOT_TOKEN` — токен бота от @BotFather
   - `FAMILY_ADMIN_TELEGRAM_ID` — Telegram ID главы семьи (опционально,
     можно задать позже)
2. Поднять всё одной командой:

   ```bash
   docker compose up --build
   ```

   API будет доступен на `http://localhost:8080`.

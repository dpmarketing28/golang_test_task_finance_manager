# Финансовый менеджер семьи — Telegram-бот + REST API

Тестовое задание: сервис учёта семейных расходов. Член семьи пишет боту в
Telegram «кофе 350» — бот понимает текст через LLM, сам определяет сумму,
категорию и дату, и сохраняет трату. Глава семьи может смотреть и
редактировать траты всех членов семьи — как через того же бота, так и
через веб-панель, без авторизации, как и требует задание.

## Что реализовано

- **Модель данных.** Член семьи (`member`/`admin`) и трата (фиксированные
  категории: еда, транспорт, жильё, развлечения, здоровье, покупки,
  другое — любая покупка, не подходящая ни под одну из них, уходит в
  «другое»).
- **Правило доступа** на уровне бизнес-логики (`internal/usecase`):
  обычный член семьи видит и правит только свои траты; глава семьи видит
  и правит траты всех. Это правило единое и для REST API, и для бота —
  переиспользуется, а не продублировано.
- **PostgreSQL**: две таблицы (`users`, `expenses`), миграции применяются
  автоматически при старте приложения.
- **REST API** — CRUD над тратами + список членов семьи (см. таблицу
  ниже). Он же используется ботом внутри процесса (не по HTTP) для
  выполнения операций, которые просит пользователь.
- **Telegram-бот с LLM-агентом.** Понимает свободный текст без команд и
  кнопок: добавляет, показывает, изменяет, удаляет траты. Агент сам
  решает, какой нужен CRUD-вызов, через tool calling (function calling) у
  LLM — список доступных функций в `internal/agent/tools.go`.
  Глава семьи может через бота же спросить про конкретного члена семьи
  по имени («сколько потратил сын») — агент сам резолвит имя в Telegram
  ID через `list_family_members`.
- **LLM подключается через конфиг** (`LLM_API_KEY`/`LLM_BASE_URL`/
  `LLM_MODEL`), без привязки к конкретному провайдеру — подходит любой
  OpenAI-совместимый Chat Completions API (сейчас настроено на бесплатную
  модель через OpenRouter).
- **Веб-панель главы семьи** (`http://localhost:8080/`) — список трат
  всех членов семьи с фильтрами (по человеку/периоду/категории),
  добавление, инлайн-редактирование, удаление. Одна статическая страница
  (HTML/CSS/JS без сборки), встроенная в тот же Go-бинарник через
  `go:embed` — отдаётся тем же процессом, что и REST API, без отдельного
  фронтенд-сервиса в `docker-compose.yml`. Без авторизации, как и
  требует задание.
- **Тесты**: 50+ тестов на HTTP-слое и на агенте (включая цикл tool
  calling на фейковом LLM-клиенте, без реальной сети), `go test ./...`.

## Архитектура

```
cmd/
  app/                — точка входа: собирает зависимости и запускает (без бизнес-логики)
  llmcheck/           — отдельная утилита: проверить, что LLM_API_KEY/LLM_MODEL реально работают
internal/
  domain/             — сущности и бизнес-правила, без внешних зависимостей
  usecase/            — CRUD над тратами + проверка прав доступа (используется и REST API, и ботом)
  storage/postgres/   — репозитории + SQL-миграции
  httpapi/            — REST API (chi) + встроенная веб-панель (webui/, go:embed)
  telegram/           — адаптер Telegram-бота (long polling)
  agent/              — NLU-агент: системный промпт, схемы инструментов, цикл tool calling, память на пользователя
  llm/                — низкоуровневый клиент OpenAI-совместимого Chat Completions API
  config/             — загрузка конфигурации из .env / переменных окружения
```

Слоёв ровно столько, сколько нужно для разделения ответственности:
транспорт (`httpapi`, `telegram`) ничего не знает о SQL или о LLM,
бизнес-правила (`usecase`) ничего не знают о Telegram или HTTP, а агент
(`agent`) просто вызывает тот же `usecase`, что и REST API.

## Стек

- Backend: Go 1.27, `chi` (роутинг), `pgx` (Postgres), `go-telegram-bot-api`
- БД: PostgreSQL 16
- LLM: любой OpenAI-совместимый провайдер (по умолчанию — OpenRouter)
- Запуск: Docker Compose

## Переменные окружения

Все — в `.env` (образец в `.env.example`):

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather |
| `DATABASE_URL` | строка подключения к Postgres |
| `HTTP_ADDR` | адрес REST API, по умолчанию `:8080` |
| `FAMILY_ADMIN_TELEGRAM_ID` | Telegram ID главы семьи (кто получит роль `admin` при первом обращении к боту); можно оставить пустым и задать позже |
| `LLM_API_KEY` | ключ LLM-провайдера |
| `LLM_BASE_URL` | базовый URL API, по умолчанию `https://openrouter.ai/api/v1` |
| `LLM_MODEL` | модель, например `nvidia/nemotron-3.5-super-vl:free` |

## Запуск

### Через Docker (рекомендуемый способ)

```bash
cp .env.example .env   # и заполнить реальными значениями
docker compose up --build
```

Поднимет Postgres и приложение одной командой. Веб-панель — на
`http://localhost:8080/`, REST API — на `http://localhost:8080/api/...`.

### Без Docker (для разработки)

Нужен локально запущенный Postgres с базой, указанной в `DATABASE_URL`.

```bash
go run ./cmd/app
```

Проверить, что LLM-ключ рабочий, можно отдельно, не поднимая бот/БД:

```bash
go run ./cmd/llmcheck
```

## REST API

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/expenses` | добавить трату |
| `GET` | `/api/expenses?user_id=&category=&from=&to=` | список с фильтрами |
| `GET` | `/api/expenses/last?user_id=` | последняя добавленная трата |
| `GET` | `/api/expenses/{id}` | одна трата |
| `PATCH` | `/api/expenses/{id}` | изменить трату |
| `DELETE` | `/api/expenses/{id}` | удалить трату |
| `GET` | `/api/users` | список членов семьи |
| `GET` | `/api/categories` | список допустимых категорий |

Актёр (от чьего имени запрос) определяется заголовком
`X-Telegram-User-Id`. Без заголовка запрос выполняется с правами главы
семьи (полный доступ без авторизации) — расчёт на то, что веб-панель
никак не аутентифицируется, как и указано в задании.

## Известные ограничения

- Память диалога у агента (`internal/agent/memory.go`) живёт только в
  процессе и не чистится по TTL — для размера одной семьи это не проблема,
  но при большом числе пользователей потребовало бы эвикции.
- Обработка сообщений бота распараллелена по пользователям (чтобы один
  долгий LLM-запрос не блокировал всех), но не гарантирует строгий
  порядок двух сообщений, отправленных одним человеком почти одновременно.
